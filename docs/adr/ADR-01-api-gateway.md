# ADR-01: Выбор Django REST Framework для API Gateway

## Status
...

## Context

В системе требуется реализовать API Gateway, который будет:
- выступать единой точкой входа для клиентского приложения (React)
- обрабатывать аутентификацию и авторизацию пользователей (JWT)
- управлять доступом к ресурсам
- агрегировать данные из нескольких сервисов (PostgreSQL, FastAPI)
- обеспечивать стабильную и расширяемую бизнес-логику

Рассматривались следующие варианты:
- Django REST Framework (DRF)
- FastAPI
- Node.js (Express/NestJS)

Ключевые требования:
- встроенная работа с пользователями и авторизацией
- удобная работа с базой данных
- быстрая разработка CRUD и бизнес-логики
- возможность масштабирования

## Decision

В качестве API Gateway выбран Django REST Framework (DRF).

DRF используется как основной backend-сервис, который:
- обрабатывает все входящие HTTP-запросы от клиента
- выполняет аутентификацию (JWT)
- взаимодействует с базой данных через ORM
- вызывает аналитический сервис (FastAPI) при необходимости
- инкапсулирует бизнес-логику системы

## Consequences

### 👍 Плюсы

- Встроенная ORM (Django ORM)
  - упрощает работу с PostgreSQL
  - снижает количество ручного SQL

- Готовая система аутентификации и пользователей
  - легко реализуется JWT (через simplejwt)
  - не нужно писать безопасность с нуля

- Быстрая разработка CRUD
  - serializers, viewsets, generic views

- Зрелая экосистема
  - много библиотек
  - стабильность

- Хорошо подходит для роли API Gateway
  - централизует бизнес-логику
  - удобно контролировать доступ

### 👎 Минусы

- Синхронная модель по умолчанию
  - хуже подходит для высоконагруженных async-задач

- Более тяжёлый фреймворк
  - выше потребление ресурсов по сравнению с FastAPI

- Меньшая производительность на "чистых" API-запросах
  - из-за abstraction слоя Django

- Может стать bottleneck при росте нагрузки
  - требует горизонтального масштабирования

## Alternatives

### 1. FastAPI

Плюсы:
- высокая производительность
- нативная асинхронность
- удобен для микросервисов

Минусы:
- отсутствует встроенная ORM и полноценная система пользователей
- больше ручной работы для авторизации и бизнес-логики
- хуже подходит как API Gateway с "богатой" доменной логикой

Причина отказа:
FastAPI лучше подходит для вычислительных и асинхронных сервисов (аналитика), чем для централизованного API Gateway.

---

### 2. Node.js (Express / NestJS)

Плюсы:
- высокая производительность
- хорош для real-time

Минусы:
- требует больше настройки (ORM, auth, структура)
- усложняет стек (добавление второго языка)

Причина отказа:
увеличение сложности системы без значительных преимуществ для текущего проекта.
