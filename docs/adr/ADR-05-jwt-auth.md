# ADR-05: Использование JWT для аутентификации

## Status
Accepted

## Context

В системе требуется реализовать механизм аутентификации пользователей для API Gateway (DRF).

Ключевые требования:
- поддержка клиентского приложения (React)
- масштабируемость (несколько сервисов)
- отсутствие привязки к серверному состоянию
- возможность работы в распределённой архитектуре
- безопасность

Рассматривались варианты:
1. Сессионная аутентификация (Django sessions)
2. JWT (JSON Web Token)

## Decision

Для аутентификации пользователей выбран механизм JWT.

DRF использует JWT для:
- аутентификации пользователей
- передачи информации о пользователе в каждом запросе
- работы без серверного хранения сессий

Используется схема:
- access token (короткоживущий)
- refresh token (для обновления access)

## Consequences

### 👍 Плюсы

- Stateless архитектура
  - сервер не хранит состояние сессий
  - упрощает масштабирование

- Подходит для микросервисов
  - токен можно использовать между сервисами
  - не требуется общий session storage

- Удобен для SPA (React)
  - клиент хранит токен
  - простая интеграция

- Снижение нагрузки на сервер
  - нет обращений к session storage

- Гибкость
  - можно добавлять кастомные claims (роли, права)

### 👎 Минусы

- Сложность отзыва токенов
  - токен действителен до истечения срока

- Необходимость безопасного хранения на клиенте
  - риск XSS при хранении в localStorage

- Усложнение логики (refresh tokens)
  - требуется механизм обновления

- Размер токена больше, чем session id
  - передаётся в каждом запросе

## Alternatives

### 1. Сессионная аутентификация (Django sessions)

Плюсы:
- простота реализации
- встроена в Django
- легко инвалидировать сессии

Минусы:
- требует хранения состояния на сервере
- плохо масштабируется (нужен общий session storage)
- неудобна для SPA и мобильных клиентов
- сложнее использовать в микросервисной архитектуре

Причина отказа:
сессионная модель хуже подходит для распределённой архитектуры и API-first подхода.

---

### 2. Хранение сессий в Redis

Плюсы:
- централизованное хранение сессий
- можно масштабировать

Минусы:
- дополнительная инфраструктура
- сохраняется stateful модель
- усложнение системы

Причина отказа:
JWT позволяет избежать хранения состояния и упрощает архитектуру.
